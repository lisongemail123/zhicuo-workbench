# 知错 · 个人错题本工作台

一个会随学习反馈推进复习的个人错题本：**录入 → 结构化归档 → 学习与状态回写 → 报告与下一步 → A4 组卷打印**。

根据《我用 WorkBuddy 做了个会自己推进的错题本》的需求实现，采用奶油底、砖红与深可可配色。2.0 增加 **OCR、可配置大模型与自动答案解析**，前端使用原生 HTML/CSS/JavaScript，后端提供同源 AI 转发接口。

[打开已发布的工作台](https://cuoti-study-desk-k7m3.doublecurry16.chatgpt.site) · [配置模型与 OCR](https://cuoti-study-desk-k7m3.doublecurry16.chatgpt.site/#ai)（使用获授权的账户访问）。

## 新增：OCR 与自动解题

- **本地 OCR**：Tesseract.js 7.0.0 在浏览器内识别中英文印刷体，无需 API Key；支持简体、繁体与英文。首次需联网下载引擎和字库，图片不上传给字库/CDN 服务。
- **视觉 OCR**：使用已配置且支持图像输入的模型识别照片，结果可编辑；适合本地 OCR 难以识别的公式或手写内容，但仍需核对原题。
- **模型配置**：支持多套服务商、API Base URL、模型 ID、图像能力和超时配置，可读取模型列表、测试连接，并分别选择默认解题模型与视觉模型。
- **两种协议**：OpenAI 兼容 Chat Completions 和 Anthropic Messages。提供 DeepSeek、通义千问、OpenAI、硅基流动、Anthropic 预设，以及自定义兼容接口。
- **自动解题**：根据题干生成参考答案、分步解析、知识点和有依据的错因建议。新题录入和已有错题均可使用。
- **一键流程**：上传照片后选择“OCR 识别”“自动解题”或“识别并解题”。可设置上传后自动识别、识别后自动解题。
- **核对后采用**：识别和解题结果先预览，可修改后填入。不会自动标记为已掌握，不改变既有复习轮次和学习记录。题目在等待期间被修改时，过期结果不会覆盖新内容。

### 如何配置

1. 打开左侧“模型与 OCR”，点击“添加模型配置”。
2. 选择服务商，核对 API Base URL，输入你自己的 API Key。
3. 填写模型名称，或点击“读取模型列表”后选择。模型 ID 以自己的账户实际可用列表为准。
4. 如用于视觉 OCR，确认该模型确实支持图片，并勾选图像能力。
5. 可先测试连接，再保存配置，选择默认解题模型与 OCR 方式。
6. 进入“录入错题”，上传照片或粘贴题干，生成并核对答案解析后归档。已有错题可打开详情，点击“AI 解题”。

API Base URL 应填写基础路径，不必追加 `/chat/completions`。例如 DeepSeek 为 `https://api.deepseek.com`，OpenAI 为 `https://api.openai.com/v1`。百炼可按账户地域与业务空间更换地址。自定义服务需为公网 HTTPS 地址；本版本后端不连接用户电脑上的 localhost 或内网模型。

### 密钥与资料

模型配置保存在本地 `zhicuo.ai.config.v1`，其中**不含 API Key**。Key 单独保存在当前标签页的 `sessionStorage` 中，可在设置页一键清除；不会写进 GitHub、错题备份或服务端持久存储。

调用时，浏览器通过同源 `/api/ai` 将本次 Key 与题目交给后端；后端只把该 Key 转发给用户配置的接口，不跟随重定向、不转发站点登录信息、不回显服务商原始错误。使用云端模型时，题干或照片会发送给所选服务商，并按其规则计费。本地 OCR 不调用解题 API。

## 原有学习功能

- 工作台：今日待复习、收录与掌握情况、学习节奏、最近错题与薄弱知识点。
- 三步归档：原题、结构化分析、知识路径与首次复习日一起保存。
- 错题档案：按学科、状态、错因、关键词筛选；收藏、多选、批量学习、选题组卷与回收站。
- 学习中心：按错题或知识点学习，独立思考后查看解析，标记“已掌握”或“仍需复习”。
- 知识体系：前置关系、分层路径、讲解、示例与相似练习；支持自定义并检测循环依赖。
- 学习报告：复习趋势、错因分布、掌握度矩阵与下一步题单，可回到具体错题。
- 组卷打印：到期、薄弱知识点、高频错因、随机四种自动策略，以及手动勾选；A4 练习卷与答案页分开。
- 个人空间：每日目标、示例清除与包含照片、知识关系、AI 来源和学习记录的 JSON 备份恢复。

八类固定错因：概念不清、知识遗忘、审题遗漏、计算失误、方法不当、推理不严、表达不规范、时间不足。

## 本地运行

推荐 Node.js 24.15+ LTS，或 22.22.2+ LTS。

```bash
git clone https://github.com/lisongemail123/zhicuo-workbench.git
cd zhicuo-workbench
npm ci
npm start
```

打开 <http://127.0.0.1:4173>。可用 `PORT=3000 npm start` 修改端口；Windows PowerShell 使用 `$env:PORT=3000; npm start`。

本地服务默认只监听 `127.0.0.1`，同时提供静态页面与 `/api/ai`。2.0 不能仅用 Python 静态服务器运行完整 AI 功能：纯静态托管可浏览错题并使用本地 OCR，但自动解题和视觉 OCR 需要同源网关。

## 构建与部署

```bash
npm run build
```

生成 `dist/server/index.js`，是带有 `fetch(request)` 入口的独立 Cloudflare Worker ES Module。HTML、CSS、前端 JS、OCR 主库和 worker 被嵌入部署文件，`/api/ai` 提供模型转发。无需服务端数据库或预置平台 API Key。

本项目 GitHub 仓库不包含个人 Sites 身份。使用 Sites 部署时，保留或创建属于自己站点的 `.openai/hosting.json`，填写真实 `project_id`，并采用 Worker 部署配置（不设置 `static`）。部署产物为该清单与 `dist/server/index.js`。不要使用其他人的站点身份。

OCR 主库及 worker 已随源码保留。若需要重新生成：

```bash
npm run vendor:ocr
```

字库与 WASM 默认按需在线加载并缓存；依赖说明与许可证见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 复习与数据规则

新题默认 1 天后首次复习；标记掌握后依次在 2、4、7 天后复测，第四轮完成。仍需复习则重置为 1 天后。已掌握但仍有复测日期的题，到期后仍会进入清单。AI 生成不会修改这些学习状态。

当前掌握率按在册错题的状态计算，趋势图统计复习次数；回收站题目不计入当前掌握率或到期清单，但保留历史记录。没有关联错题的知识点不计入掌握率。

学习数据仍保存在当前浏览器 `localStorage`，键名保持 `zhicuo.workbench.v1`，兼容旧版数据，不跨设备同步。不同域名、端口或浏览器拥有各自存储；清除浏览器数据会删除本地错题。迁移请先导出 JSON，再在目标设备或地址导入。导入会替换当前学习空间，请先保存原有备份。

照片支持 JPG/PNG/WebP，单张不超过 1.5 MB；备份导入不超过 8 MB，实际容量受浏览器配额限制。推荐一题一张、清晰拍摄。印刷体本地识别效果通常优于手写，复杂公式、模糊字迹和图示条件均需核对。模型也可能出错，采用前请检查答案与解析。

相似训练题仍来自可编辑的内置题库。打印使用浏览器原生打印，建议 A4 纵向、关闭页眉页脚；线下完成后回到学习中心更新掌握状态。
